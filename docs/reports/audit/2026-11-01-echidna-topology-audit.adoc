== Scope and method

Audit scope:

* What proof-burrower's ECHIDNA integration *actually does* at HEAD
  (`39673264`), line by line, as distinct from what
  `docs/ECHIDNA-INTEGRATION.adoc` proposes.
* Whether the proposed ledger topology is compatible with the estate's
  no-point-to-point VeriSimDB/VCL invariant.
* Whether strict receipt validation survives that reconciliation.
* Where the repository stands against the estate's graded-proof ladder,
  and what is missing to reach *Grade 3*.

Method: read the shipped Rust sources and the normative estate
documents; no claim below rests on inference where a file could be
opened instead. Every finding cites `file:line` in this repository or a
path in an estate repository.

Line numbers for `crates/**` are at HEAD and are unchanged by this work.
Line numbers for `docs/ECHIDNA-INTEGRATION.adoc` are those of the
*audited* revision `39673264`, because this audit is what prompted the
edits to that file; they no longer resolve against the edited document,
which is cross-referenced by section anchor instead.

=== What could not be verified in this environment

Stated plainly, so no reader mistakes an unrun check for a pass:

* **No Rust toolchain is present** (`cargo`, `rustc`: absent) and
  `static.crates.io` is unreachable from this sandbox, so
  `cargo test`, `cargo clippy` and the 95% `llvm-cov` floor were *not*
  run. Every statement about Rust behaviour below comes from reading the
  source, not from executing it.
* The canonical text of the **no-point-to-point invariant itself** is not
  in this repository (`grep -rn "VCL"` over the tree returns zero hits)
  and a GitHub code search for its wording was rate-limited. Its
  *substance* is corroborated by Mathesis §8 and by
  `verisimdb/docs/vcl-vs-sql.adoc`, both of which are cited above; the
  policy document that names it is not cited because it was not found.
* Whether `verisimdb-client` is published on crates.io could not be
  checked (crates.io unreachable). This matters and is flagged in
  <<why-not-an-adapter-now>>.
* The two repository checks that *are* runnable here were run, before and
  after this change, with identical output:
  `bash tests/aspect_tests.sh` (one pre-existing FAIL: it greps
  `verification/proofs/README.adoc` for the *words* `sorry` and
  `Admitted`) and `bash scripts/validate-template.sh .` (one pre-existing
  ERROR). Neither is caused by, or affected by, this change.
+
The template ERROR is a *case mismatch, not a missing directory*, and the
distinction matters enough to correct here. `scripts/validate-template.sh`
line 105 checks for `src/interface/abi` and lines 193-195 expect
`Types.idr`, `Layout.idr` and `Foreign.idr` inside it. The repository spells
that directory `src/interface/Abi`, and all three files are present as real
modules — `Abi.Types` (112 lines), `Abi.Layout` (128), `Abi.Foreign` (83) —
with no `believe_me`, `really_believe_me`, `assert_total` or
`%default partial` in any of them. The Idris2 ABI layer therefore exists and
is not the stub its absence would suggest; the checker is looking for the
wrong capitalisation. Fixing it is a one-line change on either side, but it
settles a naming question (`Abi` versus `abi`) that also decides the module
names and any import paths downstream, so it is recorded as T-9 rather than
made unilaterally.

[[current-behaviour]]
== Finding A — what actually runs end to end

There is exactly one live integration with ECHIDNA and it is a one-shot
subprocess. Three `Command::new` call sites exist in the whole of
`crates/*/src`, and all three are accounted for:

[cols="1,2,3"]
|===
|Call site |Invocation |Purpose

|`attempt.rs:388` |`echidna prove <probe> --prover Isabelle -t <secs>`
 plus optional `--project-root <p>`, `--sandbox <m>`, `--output json`
 (`prove_command`, `attempt.rs:387-409`)
|The proof attempt.

|`echidna_contract.rs:196` |`echidna prove --help`
|Capability detection, once per binary per process, cached in a
 `Mutex<HashMap<PathBuf, OutputMode>>` (`echidna_contract.rs:166-169`).

|`oracle.rs:99` |`julia [--project=P] <script> <descriptor>`
|The optional tropical-types pre-proof oracle.
|===

Consequences, all verified in source:

* **No socket, no network, no storage client is involved in the proof
  path.** There is no `TcpStream`, no `reqwest`, no `tokio`, and no
  `async fn` anywhere in `burrower-core/src`. The only
  `UnixStream::connect` in the crate is inside a test
  (`serve.rs:302`).
* **Capability detection is conservative.** `detect_output_mode`
  (`echidna_contract.rs:188`) enters contract mode only when `--output`
  appears as a *whole* option token in `prove --help`
  (`help_advertises_output`, `:176`), so `--output-dir` does not
  accidentally opt a binary in. A binary that advertises the flag and
  then rejects it is demoted once and remembered
  (`run_probe`'s retry loop, `attempt.rs:342-363`;
  `rejected_output_flag`, `echidna_contract.rs:239`).
* **Strict receipt validation is intact.** `parse_prove_result`
  (`echidna_contract.rs:129`) requires: exactly one line; a successful
  I-JSON parse; **byte equality with its own RFC 8785 canonical form**,
  computed by `serde_json_canonicalizer`; an exact `schema` match against
  `echidna.prove.result/1` (`:39`); and the full field shape via serde.
  Byte equality is what enforces the I-JSON limits a parser alone will
  not — a duplicate key collapses to one member and an integer past
  ±(2^53−1) re-serialises differently, so both fail as non-canonical
  (`:139-146`). A violation becomes `AttemptResult::Failed` carrying
  "contract violation" and is **never re-read as text**
  (`interpret_contract`, `attempt.rs:417-462`). `verified` with a
  non-zero exit also fails: failure evidence wins.
* **The legacy path is genuinely a fallback, and it is labelled.** A
  success read from text markers carries `receipt: None`
  (`interpret_legacy`, `attempt.rs:464`) and the ledger explanation says
  so in words: "legacy text markers: a warrant, not a receipt"
  (`explain`, `attempt.rs:610-638`).
* **`burrower serve` (BI-1) is implemented** — `serve.rs:112` binds a
  `UnixListener`, refuses an occupied path, `run` (`:133`) is
  thread-per-connection, `dispatch` (`:185`) accepts
  `ping|swarm|attempt|ledger`. It has **no authentication and no peer
  credential check** (no `SO_PEERCRED` anywhere in the file). It is an
  *inbound* endpoint: nothing in this repository dials it, and no
  echidna or echidnabot client calls it.

=== The live CI path exercises the legacy branch

`.github/workflows/proof-safety.yml` checks out `hyperpolymath/echidna`
at `556d64687a8872026c81e4689ac3d574c7acc6ce`, builds it, and runs
`tests/e2e.sh`, which runs `live_isabelle.rs --ignored` against real
Isabelle. That pin predates `--output json`. So the *only* end-to-end
proof run in CI goes through `interpret_legacy`, and the contract path —
including every receipt rule above — is covered **only by fake
binaries** in `attempt::tests` and `echidna_contract::tests`. The
repository already says this (`docs/status/TEST-NEEDS.adoc:33-34`,
`docs/status/ROADMAP.adoc:22`); it is restated here because it is the
single largest gap between "implemented" and "demonstrated".

=== The receipt is written and never read

`receipt_extra` (`attempt.rs:589`) stores the receipt at
`extra.receipt` and `run_playbook` writes it. **No production code path
ever reads it back.** `Ledger::read_all` (`ledger.rs:133`) deserialises
each line and skips malformed ones; `extra` is an opaque
`serde_json::Value` (`ledger.rs:63`). Receipts are, today, write-only.
This is harmless while Burrower is the sole writer and becomes a
soundness hole the moment it is not — see <<laundering>>.

== Finding B — planned topology vs the no-point-to-point invariant

`docs/ECHIDNA-INTEGRATION.adoc` is candid that most of it is planned,
but four of its proposals describe point-to-point wiring that the
estate's shared-data-plane model rules out. None of them is implemented;
all four would violate the invariant if built as written.

[cols="1,3,3"]
|===
|Proposal |As written |Conflict

|EI-2 (`:262`, `:269`)
|`echidna suggest <file>:<lemma> [--burrower <socket>]` — "send the goal
 to the Burrower swarm; receive back ranked candidate homes"
|echidna dials a Burrower socket: a repo↔repo point-to-point channel.

|BI-1 (`:404`)
|"ECHIDNA's `--burrower` flag and echidnabot's swarm-findings hook both
 consume this socket"
|Same channel, described as the intended integration surface.

|BI-3 (`:428`)
|"Both write to the *same* ledger via a shared socket"
|Point-to-point *and* a second writer, contradicting
 `ledger.rs:95` ("One writer; many readers") and `ledger.rs:17` ("No
 locking yet — single writer assumed").

|EBI-2 (`:361-370`)
|`backend = "verisimdb"  # or "s3" or "local"` with
 `url = "vsdb://swarm/burrow-ledger"`
|A per-repo client talking straight to a data store, past VCL. `s3` is
 not a VeriSimDB modality store at all, so "or s3" offers an
 uncontrolled bypass as a peer option.

|EI-3 (`:292-315`)
|ECHIDNA appends `LedgerRecord`s to a configured file path
|A second process appending to a file with no locking and no

=== What the estate actually requires instead

Two estate documents carry the substance of the invariant, and they agree
in direction:

* `verisimdb/docs/vcl-vs-sql.adoc` — "VCL's **preferred** write path is
  the Octad API (Rust core or Elixir orchestration layer), not the
  language. VeriSimDB treats writes as coordinated multi-modal
  operations that must maintain consistency across all eight modality
  stores … a bare `INSERT` cannot by itself express the cross-modal
  invariants an octad write requires." The Octad API is
  `POST /api/octads`, `PUT /api/octads/:id`, `DELETE /api/octads/:id`.
* Mathesis §8 — "Agents must not have direct write-access to mutate the
  canonical SQLite index. Provide a strict 'write-back' or 'nomination'
  API where agents can submit discovered broken links, missing
  verification receipts, or false positives for human or CI-gated
  review."

proof-burrower is an agent in that sentence. So the ledger's
cross-repository exchange must be a *nomination into a shared layer*,
not a socket between two repositories and not a private S3 bucket.

[[why-not-an-adapter-now]]
=== Why this change narrows the claim instead of writing the adapter

The reconciliation had two permitted shapes: route through a
backend-specific VCL adapter, or narrow the topology claim. Narrowing was
chosen, for reasons that are themselves findings:

* The only VCL Rust surface in the estate is `verisimdb-client` v0.1.0
  (`hyperpolymath/verisimdb/connectors/clients/rust`), whose
  `execute_vcl` / `explain_vcl` are `async fn` over `reqwest`, and whose
  `Cargo.toml` pulls `tokio = { version = "1", features = ["full"] }`.
  `burrower-core` has **no async runtime by explicit design**
  (`serve.rs:27-31`: "burrower-core has no async runtime today … spawning
  a std thread per accepted connection is cheaper than pulling in
  tokio"), and it is compiled to `wasm32-unknown-unknown` by
  `burrower-wasm`, where neither tokio nor reqwest works. Adopting the
  client as-is would break one of the two.
* Whether that crate is published on crates.io is **unverified here**.
  If it is git-only, the blocker this repository already documents for
  `ijson-jcs` applies verbatim (`docs/ECHIDNA-INTEGRATION.adoc`,
  §prove-result-contract): "the estate crate … is private and this
  repository is public (a git dependency on it cannot be fetched by CI
  or by anyone who downloads the repo)".

So the honest state is: **there is no ledger backend other than the local
JSONL file, and the topology claims that implied otherwise have been
narrowed.** The adapter seam is now a written precondition on any future
backend work rather than a sketch:

. `ledger::Ledger` remains the single write point. Nothing else appends.
. A future backend is an implementation behind `Ledger`, selected by
  configuration; the JSONL file is the only one that exists.
. The VeriSimDB backend, when it lands, goes through VCL / the Octad API
  — never a direct modality-store connection and never S3.
. Receipts cross that seam unchanged and are re-validated on read
  (<<laundering>>).
. Publication into Mathesis is a *nomination*, per Mathesis §8, carrying
  the fields §6 requires (<<grading>>).

[[laundering]]
=== Receipt laundering: the hole the planned topology would open

Because `read_all` validates nothing in `extra`, any *second* writer —
EI-3's echidna writer, an EBI-2 upload/download round trip, or a
hand-edited ledger — can make a record that *looks* receipt-backed. A
consumer that trusts `extra.receipt` on sight would then report a
receipt for a proof nobody checked. Today this is latent; the planned
topology makes it live.

Requirement recorded for whoever builds the seam, and now stated in
`docs/ECHIDNA-INTEGRATION.adoc`:

* A record read from anywhere other than a same-process
  `ProofReceipt::from_result` is a **claim**, not a receipt.
* Before a read record counts as receipt-backed, re-validate its shape
  against the contract and **re-derive `result_id`** with
  `ids::content_id` over the receipt's contract fields; a mismatch means
  the payload was altered in transit or in storage.
* A record that fails either check is demoted to a warrant, and the
  demotion is recorded rather than silently dropped.

This is the same rule PROOF-POLICY §2.1 applies to proofs — "Prior
`--safe` … successes are historical evidence, not receipts for this new
combined profile" — applied to transported evidence.

=== The receipt carries the wrong fields for the ladder

`ProofReceipt` (`attempt.rs:108-124`) is `schema`, `prover`, `axioms`,
`confidence`, `echidna_version`, `result_id`. Mathesis §6 requires more
than that of anything it will index:

* "**Do not flatten proof confidence into a percentage.** Record exactly
  whether a result is Open, Claimed, Grade 3, Grade 2i/ii, or Grade 1."
  There is **no grade field**. `confidence: Option<f64>` is transported
  and is `null` unless echidna has a receipt-backed figure, so nothing is
  flattened *today* — but the field is the invitation, and EBI-3
  (`:377-396`) takes it: "Confidence threshold: configurable, defaults to
  **0.8** … auto-open a PR with the suggested edit." That is a percentage
  driving an edit on `main`, and Mathesis §13 also forbids the
  corroboration it assumes: "Do not allow agent-generated evidence to
  count as independent corroboration."
* "Mathesis must track the exact Git commit hash of the verification
  receipt." `echidna_version` is a **version string, not a commit hash**.
  The one place this repository does pin a commit is CI
  (`proof-safety.yml`, `556d6468…`), and that pin never reaches the
  receipt.
* Axiom tracking is present (`trust.axioms`) but is not mapped onto the
  Trusted-Base-Reduction dispositions — (a) DISCHARGED, (b) BUDGETED
  (`// TRUSTED: <kind>; <budget>`), (c) NECESSARY AXIOM
  (`-- AXIOM: <name>; <justification>`). An unclassified axiom in a
  receipt is exactly the "unfalsifiable 'covered by tests'" the policy
  warns about.
* No `Superseded` / `Regressed` status exists anywhere, though Mathesis
  §6 requires both.

Burrower's Isabelle results are on the estate's **Engineering Path**
(Mathesis §3), not the Theory Path, and a Grade 1 claim requires the
verified-checker-API route (isabelle server instances, AXLE, coq-lsp).
Burrower shells out to `echidna prove`; whether that satisfies Grade 1 is
echidna's property, not Burrower's. **Burrower must therefore record the
grade it was told and never assert one it derived.**

=== A real correction to the proof-debt count

`docs/tech-debt-2026-05-26.adoc` §1 reports `Idr-blv = 6`. All six are

== Decisions taken in this change

. **Narrowed, not implemented.** The topology claim is now scoped to what
   exists: a local single-writer JSONL ledger, plus an unauthenticated
   same-host Unix socket that no estate component uses. The VCL/Octad
   adapter is recorded as a precondition on future backend work, with the
   two blockers that stopped it being written now.
. **Receipt validation retained and extended forward.** Nothing in
   `echidna_contract.rs` or `attempt.rs` was weakened — the byte-equality,
   schema-exactness, shape and failure-evidence-wins rules are untouched
   and remain the only way a receipt is created. The read-path
   re-validation rule is written down as a requirement on the seam, not
   implemented, because implementing it would mean shipping Rust that
   cannot be compiled or tested in this environment.
. **Grade posture stated rather than improved by assertion.**
   `docs/proof-debt.adoc` was created, `CLAUDE.md` now names
   `PROOF-POLICY.adoc` as normative, and the roadmap carries the Grade 3
   obligations. No document now claims a grade the repository has not
   earned; per Mathesis §11 the unresolved evidence is reported plainly.
. **epistemic-types stays a pattern.** `5422cd5` adding real Kripke
   semantics for the factive/non-factive split is a reason to *re-read*
   the receipt/warrant distinction, not to take a dependency: the crate
   is Agda, this workspace is Rust plus wasm32, and the audit gate in
   `docs/AUDIT.adoc` forbids release claims that outrun their artefacts.

=== Consequence: two results moved from debt to Grade 3

With Agda working, the semantic rewrite the audit called for in T-5 was
written and checked rather than merely specified:

* `verification/proofs/agda/Burrow/Trust.agda` — receipt versus warrant.
  A receipt is a *validated warrant*, not a second kind of object; a
  Kripke countermodel shows the legacy marker has no soundness witness, so
  `no-legacy-receipt` is a theorem and not a policy.
* `verification/proofs/agda/Burrow/Ledger.agda` — the read path.
  `no-launder` proves there is no function from a stored ledger record to
  the fact, which is the formal reason <<laundering>> is a rule rather than
  a convention.

Both follow `hyperpolymath/epistemic-types` (`5422cd5`): `Warrant` with no
`Evidence → A` field, `SoundWarrant` as the separate assumption, and a
two-world frame in the style of `EpistemicTypes.Kripke.Belief`. Copied as
a pattern, not imported.

Both check under `--safe`, `--safe --without-K --cubical-compatible` (the
estate canonical invocation) and `--safe --cubical`, with **zero warnings**
in all three. That last one matters for T-5's successor: nothing here
relies on K, so the Dedukti legs into Rocq and Lean are not blocked by the
proofs themselves.

`just proof-check-agda` passes on all three modules in the directory,
including the pre-existing `Properties.agda`.

=== Two changes that the toolchain forced

* `Justfile` `proof-check-agda` could not check the new modules as it
  stood: it passed no include path, so Agda rejected the module name
  (`Burrow.Trust` in `Burrow/Trust.agda`) with exit 42, and it used bare
  `--safe` rather than the estate's canonical flags. It also discarded
  stderr with `2>/dev/null`, which is why the failure was invisible. It now
  passes `-i verification/proofs/agda`, uses
  `--safe --without-K --cubical-compatible`, surfaces warnings, prints the
  error on failure, and removes the `*.agdai` files it generates.
  `*.agdai` is now ignored.
* Zig found a defect no existing check looks for: `zig test
  src/interface/ffi/src/main.zig` fails with `error: expected '(', found
  '{'` because the file still contains 17 unexpanded RSR template
  placeholders (`export fn {{project}}_init() …`). Nothing in CI or the
  Justfile compiles it. Recorded in `docs/proof-debt.adoc` and on the
  roadmap; not fixed here, because instantiating or deleting it is an
  owner decision about the FFI layer.
