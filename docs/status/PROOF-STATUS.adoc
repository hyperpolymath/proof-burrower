*Scope, from the 2026-11-09 audit.* DOM-2 is a *specification*: the Rust
`Ledger::read_all` (`crates/burrower-core/src/ledger.rs`) does not yet
re-validate `extra.receipt` on read, so the read rule is not a property of
the code. That Rust obligation belongs to Creusot/Pearlite and Verus
(PROOF-POLICY §1.2) and is not yet tracked as a row. `no-launder` and
`no-legacy-soundness` amount to "no map from inhabited evidence to ⊥" and do
not need the Kripke model; `epi-is-not-factive` was the identity function on
`¬ X` and has been restated as `¬ (∀ {A} → Epi A → A)`, proved from the
legacy countermodel. `revalidate` and `promote` had implicit arguments no use
site could infer; `revalidate` drops the unused one and `promote` takes its
record explicitly.

These two are the semantic record that was missing: before 2026-11-01 the
receipt/warrant distinction existed only as a Rust `Option<ProofReceipt>`
and a sentence in the ledger explanation, so nothing pinned down which
operations on it are sound. They follow the `Warrant` / `SoundWarrant` /
Kripke pattern in `hyperpolymath/epistemic-types` (`5422cd5`), copied
rather than imported.
