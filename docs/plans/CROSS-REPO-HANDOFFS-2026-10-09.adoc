Companion to `docs/plans/ULTRAPLAN-2026-10-09.adoc`. IDs match the ultraplan:
`R-` standards, `T-` rsr-template-repo, `E-` echidna, `B-` echidnabot,
`H-` hypatia, `F-` fleet bots, `A-` affinescript.

Ground rules that apply to every brief:

* Hand-offs go to a repo's maintainers, or to the named bot through that repo's
  normal intake. No standalone MCP servers; route through BoJ.
* Each brief is self-contained. The receiving side does not need this repo to
  act on it, except where a link is given.
* No brief asks another repo to convert A2ML by hand. Any A2ML-to-deed work
  follows the family mapping specs in `1-formats/deed/mappings/`.

== Standards (`hyperpolymath/standards`)

=== R-1 Root allowlist: Rust-workspace entries

*Ask.* Add gated `?` entries to the RSR root allowlist for Rust workspaces:
`Cargo.toml`, `Cargo.lock`, `crates/`, `rust-toolchain.toml`. The gate should
apply only when a `rust` capability is declared.

*Why.* Proof-burrower is a Rust workspace (`crates/burrower-cli`,
`burrower-core`, `burrower-wasm`). The template allowlist has no Rust entries,
so `check-root-shape.sh` flags a correct layout.

*Acceptance.* `check-root-shape.sh` passes on proof-burrower with no repo moves.
A repo without the `rust` capability still fails on those entries.

=== R-2 RSR 2.1.0-draft vs the deed

*Ask.* Reconcile the criteria file, which still requires A2ML descriptiles, with
the deed format (`1-formats/deed/spec/abnf/deed.abnf` v1.1.0). Add the deed as
an accepted record for `rsr-profile`, `anchor`, and `clade`. Move `scripts/check-rsr-profile.sh` from
`.machine_readable/rsr-profile.a2ml` to the deed clause.

*Why.* `rsr-criteria-v2.a2ml` criteria 3.1.8, 3.1.9, and 3.2.2 point to A2ML
paths. The deed is the target format for new work.

*Acceptance.* A repo with a deed `(rsr-profile …)` clause and no A2ML passes
3.2.2 under the checker. The 2.1.0-draft status is stated explicitly in the spec.

== echidna (`hyperpolymath/echidna`)

=== E-1 Tag the prove-result contract

*Ask.* Cut a tagged release that includes the `echidna.prove.result/1` contract
(first in commit `a71aa2c`, 2026-10-05, PR #409). Current `main` is `822cfc9`.
Echidna's Cargo version is `2.3.0` and `echidna-core` is `0.2.0`.

*Why.* proof-burrower's `proof-safety.yml` pins a commit SHA
(`556d6468…`, pre-contract). A tag is easier to pin and review.

*Acceptance.* A tag exists. `prove --output json` at that tag emits the
contract for all five statuses (see E-4 for the two untested ones).

=== E-2 Stepwise proof-state contract (the blocker)

*Ask.* Provide a real stepwise proof-state interface, with:

* `apply_tactic` returning a *new* state, not a clone of the input. Today the
  FFI path (`src/interfaces/graphql/ffi_wrapper.rs`, `FfiProverBackend::apply_tactic`)
  sends `format!("{:?}", tactic)` and returns `CoreTacticResult::Success(state.clone())`.
* A proof-state type that carries the open goals, so a consumer can read a
  sub-goal count. Today `CoreProofState::new(Term::Var(content))` holds the raw
  file text.
* `verify_proof` that reports on the state, not the file text
  (`verify_proof(&self, _state)` ignores the state).
* A JSON schema (`echidna.proofstate/1`) with a CLI or server surface, and a
  stable identifier for the state so consumers can cache by it.

*Why.* proof-burrower #105 (P3) needs step-level caching. #104 (P4) needs
`GoalReduction`. Neither can be implemented on the current surface.

*Acceptance.* A two-goal fixture lemma: applying one tactic yields one
remaining goal, and the sub-goal count is reported in JSON. Same input gives
the same state id. Tests run in CI.

=== E-3 `suggest` JSON contract (optional)

*Ask.* `echidna suggest` JSON output as `echidna.suggest.result/1`, following
the same discipline as the prove contract (versioned schema, JCS-canonical
output, unknown fields ignored).

*Acceptance.* A golden-output test for the schema. Not needed for #105 or #104.

=== E-4 `timeout` and `unknown` end-to-end

*Ask.* The contract spec states that `timeout` and `unknown` are covered only
by golden unit tests, because no backend that runs without an external prover
produces them. Add an end-to-end test that produces each status from a fixture
(for example, a test prover with a configurable delay or an unknown verdict).

*Why.* echidnabot and proof-burrower both act on these statuses.

*Acceptance.* `tests/prove_output_json.rs` covers `timeout` and `unknown`
end-to-end.

=== E-5 Corpus near-duplicate query (optional, low priority)

*Ask.* `echidna corpus near --format json`, so proof-burrower can dedupe against
echidna's corpus without growing its own indexer. Only after E-1 and only if
the owner wants the overlap removed.

outside the template allowlist. Treat this as a standards decision (R-1, R-2),
not an echidna-only fix. Do not hand-convert.
